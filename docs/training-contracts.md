# Train more contracts v1

The reviewed plan and five approved public seams are frozen in [the machine-readable contract](training-contracts.json). This document explains their boundary choices; the JSON contains required fields, types, reference variants and thirteen literal acceptance examples. No product implementation or tests are part of this contract freeze.

`analyze_training_pass(queue, completed_pass, reference)` produces a private, deterministic single-investor diagnostic. The original-release variant includes the actual preserved release, original calibration parent queue and existing reveal receipt. Rebuilding the release against the trusted frozen executables anchors the 180-session predictions. The receipt binds the canonical completed-pass payload hash and assisted queue hash; the received-file byte digest is separately preserved. A later revision cannot satisfy that receipt. Missing chronology is explicitly unknown; conflicting recorded evidence fails. No retrospective journal-prefix commitment is invented.

A training-round reference commits the detector executable/parameters, matching protocol, source/input hashes and predictions before display. Five-year visual context is stamped separately from the final180 detector input. One-to-one matching uses the same kind, earliest unused prediction within three sessions, never earlier availability. Certain observations are descriptive; uncertain/invalid cases are wholly unscored, and zero-denominator fractions are null. Random/enriched overlap counts once overall and once in each stratum. Differences alone do not establish a detector requirement.

`training.build_review_queue(series, config)` uses a separate single-human profile. The source object includes retained-file provenance, reviewed common-stock classification, canonical issuer/alias lineage, explicit candidate cutoffs, complete daily bars and split metadata. Cutoffs are recorded eligible sampling frames rather than every possible date. Five-year windows are open-left, minimum1200 sessions, first session within7 calendar days, exact endpoint, with Feb29 clamped. New rounds reject reported full-view splits. The normalized anonymous overview and180 detail use offsets; labels target the final20 sessions.

The complete exposure ledger accounts for all prior queues, views, human-labeled target intervals, reveals and explicit future validation reservations. Unknown provenance never means empty history. Aliases share canonical identities. Previously labeled target intervals and exact cases are excluded; broader history may recur only as recorded development exposure. Active future-validation canonical sources or full-context overlaps are excluded. Old exposed release roles are retained. Smaller batches or needs_data are valid outcomes.

`record_review_label(queue, labels, entry)` preserves the existing four decisions and three pattern kinds, requires the exact queue token and sole assigned human, derives view/reference/version/input stamps, and maintains immutable retry/revision history. `summarize_review(queue, labels)` exposes progress while incomplete; only a complete single-human pass yields a sealed snapshot and personal diagnostic. It never creates a second reviewer or changes prior consensus rules.

`request_training_round(catalog, history, request)` returns a pure created/resumed/needs_data transition. Ready and labeling are both active; a new request resumes that round. Same request ID with a different payload fails before mutation. Catalog and exposure/source fingerprints bind allocation. The adapter persists the whole request/round/queue/exposure transaction by append+fsync before acknowledgment, then replaces materialized views atomically. Tokens are checked against immutable durable commitments before any recovery write. Partial unacknowledged tails cannot lose acknowledged work.

The operator supplies trusted local raw sources, classification/alias evidence and exposure bootstrap. The adapter reparses retained bytes and verifies registry/exposure anchors on replay; embedded self-consistent hashes alone are insufficient. HTTP cannot pick paths/modules/thresholds. An isolated --training-dir supports disposable synthetic QA without touching the production pass or paper state. The new /learn routes use assigned-user/local-origin guards and hide committed answers, receipts and identities until the round is complete.

`private/training/preservation-baseline.json` captures received-byte SHA-256 for all preexisting private files plus patterns.py, review.py and evaluation.py. New training data is excluded. This broad baseline includes older synthetic QA copies as well as actual sources, queues, journals, snapshots, reveals and paper state. Hash-only capture makes no judgment about labels. Any legitimate new user change must be attributed explicitly rather than overwritten or silently excused.
