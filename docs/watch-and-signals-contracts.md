# Radar, manual watch and expanded signals

Confirmed by the user October12,2026: the three initial pattern rules, gapping up as an observation, and the test-first manual-watch interface. The existing coverage_report, detect_patterns and step_portfolio seams remain approved. This document freezes the implementation details at those interfaces; it does not create another approval gate.

## Expanded detector

A separate `gary.patterns_v2.detect_patterns(bars, as_of)` accepts the same explicit OHLCV input/cutoff as v1. The frozen original patterns/review/evaluation modules and every historical study remain byte-identical. Existing geometry is retained through v1; the new wrapper emits the expanded version/parameter stamp without changing event availability or evidence. Stock checks use the expanded detector; historical recognition/training references stay v1.

- `breaking_out`, buy: completed daily close strictly above the maximum high of the prior20 sessions times1.005, with the prior close not already above the corresponding prior20-session threshold. Exclude the current session from resistance; require21 prior bars to establish the prior crossing state. No volume rule was approved, so volume remains evidence rather than another gate.
- `rolling_over`, sell: completed close strictly below the minimum low of the prior20 sessions times0.995; the previous close was not already below its own prior threshold; the latest50-session simple close average is below the preceding50-session average. Require at least51 prior bars for the previous channel/average crossing state. Falling means latest average versus the immediately preceding completed average.
- `gapping_up`, observation: opening price at least2% above the immediately prior completed close. This is an opening-price gap versus close, not a claim that the whole intraday range remains above the prior high. Report it at that session's close; it never independently clears a buy or sell. Both gap observation and another signal can occur on the same session.

Events use kind/direction/status=completed, completion_date=available_at, reference level, pivot/level evidence, checks, window and version/hash. Only permitted bars validate; later bars cannot affect earlier events. Gaps require2 bars; short histories emit no unsupported channel events. Input is not mutated. Exact2% gap qualifies; exact0.5% breakout/breakdown does not. A run of closes already beyond a channel must not repeat the same crossing signal.

The approved paper seam accepts breaking_out alongside the two existing buy entries, and rolling_over alongside head_shoulders_top for full-position technical exits. Gap-only observations are not orders. Existing fundamental eligibility, timing, whole-share blocks, stops and no-margin policy continue to apply. No paper run/reset or real order is executed during implementation.

## Watch interface

`ManualWatchStore(directory, catalog)` owns local persistent manual membership. Catalog is an explicitly supplied mapping of symbol to reviewed/partial assessment; HTTP cannot choose filesystem paths or detector versions. Confirmed interface methods: `add(symbol, note='')`, `remove(symbol)`, `view(as_of)`. Refreshing source assessments is an adapter operation at the same interface and never directly promotes membership.

- Tickers normalize uppercase and dot-to-dash share-class spelling, maximum10characters, letters/digits plus at most one class delimiter. Blank, URL/path/index-like or oversized input rejects before writes. Notes are strings, maximum500characters. Existing entries do not duplicate; a supplied nonempty note may update the note, and blank retries preserve existing notes.
- Atomic append/rename+fsync persistence under ignored private/watch; process/file lock serializes competing updates. A repeated removal is harmless; removal archives membership rather than erasing evidence. A different store instance after restart reproduces membership and notes. Corrupt state is an error, never an empty reset.
- `view` returns each manually added ticker, note, added timestamp, data cutoff, named checks (classification, PE, yield, quarterly revenue, management, entry, allocation), status and a plain Why explaining failures and missing evidence. Missing catalog data remains missing. Vendor observations can show threshold proximity but do not establish filing/HQ clearance.
- Radar is independently derived: only a complete `coverage_report` with buy_allowed=true, no unresolved SG&A investigation, and no completed eligible entry belongs there. Unknown classification, stale/missing headquarters or incomparable quarterly evidence remain outside Radar. Allocation affordability is shown separately because stock selection and sizing are different decisions.
- A manual entry can overlap Radar or Buy-ready when evidence earns that classification; adding it is never evidence of clearance. Known failures may remain on the manual list for monitoring. Unrecognized symbols persist and show missing checks until data are available; invalid provider/security responses never create a buy.

The UI has distinct Buy, Radar, Manual watch and non-buy sections. Manual ticker entry, optional note, check refresh and removal stay on the stocks page. No initial user tickers are fabricated. Fresh clones retain the dated public research snapshot; personal watch membership and raw provider receipts remain private. Unsupported cached/current evidence never fills an empty Radar.

## Catalog records for watch checks

The caller-supplied catalog mapping uses canonical ticker keys. Each optional record contains company, coverage_snapshot (the existing coverage schema), observations (finite fractional/numeric trailing_pe, dividend_yield, revenue_growth and sga_growth; missing values stay absent), signals (expanded public detector events), chart_cutoff (ISO date), price (finite positive current/cutoff price), checked_at (offset timestamp), sources (label/url pairs), and sga_investigation_resolved (default false). Records may be partial. Observations explain numerical proximity but cannot make coverage.buy_allowed true. No passed boolean or hand-authored coverage report is accepted as clearance.

The watch view as_of is the completed market-session evaluation date. Approved fresh entries/exits must be completed, have direction/kind in the allowlist and available_at exactly as_of; chart_cutoff must equal as_of. The offset checked_at receipt must be at or after that session's close. A current technical exit blocks Buy-ready and Radar until stabilization/review; a gap alone can remain Radar context when the other gates clear. Observations from older cached prices remain visible with an explicit stale warning; stale/missing data prevent full classification. Optional observation_dates names the individual review/price dates for trailing_pe, dividend_yield, revenue_growth and sga_growth; chart refresh cannot lend freshness to an older quarter. Future/malformed observation dates are unreviewed. Existing dated research observations are useful for manual tracking but are never upgraded to current reviewed facts automatically. A malformed/mismatched coverage_snapshot yields review-needed state rather than silently using another ticker's coverage.

View return shape: {schema_version:manual-watch-view-v1, as_of, manual_list:[{symbol,note,added_at,status,company,checks:{named_key:{status,value,message}},why,sources,chart_cutoff,checked_at}], radar_list:[same assessment without personal membership], buy_ready_list:[same assessment without membership]}. Radar/buy-ready are derived from the complete catalog, not only manual membership. Manual statuses include needs_data, needs_review, filtered_out, radar, buy_ready and allocation_blocked. Test statuses per named check: pass/fail/missing/unreviewed/stale (observational proximity may have observed_pass/observed_fail but is never an evidence pass). All observer/caller inputs remain unchanged.

## Local source and website adapter

The fixed private root is private/watch, with an operator-only --watch-dir override for disposable QA. Source refresh uses two bounded public requests: five-year daily USD-equity bars and visible quote metrics. Validate provider ticker identity, reject redirects/foreign currencies/non-equity responses, and validate daily OHLCV before detection. Retain content-addressed raw receipts privately. Unknown security classification, unavailable quote metrics or failed fetches stay missing/unreviewed; failure retains earlier evidence with its actual dates. Do not silently map vendor EQUITY to operating_common.

Market checks run in bounded background jobs on add or explicit refresh, without holding the chart-label write lock. Source receipt/cache paths cannot be selected through HTTP. Manual mutations require bounded JSON with only declared fields, localhost Host and same-origin requests. Reviewed fundamental packets are operator-supplied coverage snapshots, never HTTP-supplied passed booleans. Personal notes/membership and raw data stay outside Git.

The website's fully qualified Buy List additionally applies the existing candidate-priority evidence requirement: retained provider split/dividend-adjusted daily close returns covering 330–366 days, at least 200 returns, current end date, finite nonnegative annualized sample volatility, and an explicit basis stamp. Rank lowest volatility first; show up to ten. Reported splits anywhere in that trailing-year window require price-basis review and block this measure, independently of the pattern window. No reviewed packet, incomplete volatility or a threshold-only observation can fill the Buy List. Selection and allocation checks remain separate.

The default evaluation date is a conservative completed weekday close approximation. Exchange holidays, early closes and vendor adjustment accuracy are not certified; missing the expected session stays stale instead of becoming an entry. There is no automatic daily fundamental refresh or brokerage execution in this delivery.
