# Cycle 3 public interfaces

Confirmed by the user (“Confirmed”) before new tests. The user authorized the next cycle, five-year charts, demonstrated detector corrections and frozen holdout evaluation. Existing strategy and review seams remain approved.

1. **Five-year studies at `build_review_queue`, `record_review_label`, `summarize_review`.** An explicitly versioned exploration profile selects daily bars within five calendar years through a frozen as-of date. It supplies an indexed overview plus a recent-session detail view, with the existing final-20-session completion labels. Retrospective context is never silently substituted for an existing 180-session label. Source dates, identities and predictions remain private. Prefer new sources with no original-study source overlap; incomplete lookbacks or split intersections cannot masquerade as complete validated histories.
2. **`freeze_evaluation(queue, calibration_labels, detector_version) -> release`.** Require both registered reviewers to have completed the calibration pass. Bind the immutable original queue, complete versioned label snapshot, detector source/parameter version, matching policy and predictions on the original holdout contexts before exposing those contexts. The returned release includes a derived anonymous holdout-only queue and prediction commitment. Original queue and labels remain unchanged. A frozen release is never silently replaced by later label edits or detector changes.
3. **`evaluate_detector(queue, labels, release, phase) -> report`.** Calibration and holdout use separate label stores. Reports require the frozen release, exact queue/label provenance and the committed detector predictions. Pending, uncertain, invalid and exact-offset disagreements remain unscored; random and enriched strata remain separate. Partial holdout reviews yield progress, with no recognition results until both passes are complete. Evaluation is retrospective pilot evidence, not a trading or five-year investment-performance result.

All three are local pure interfaces. Complete reports and raw sources stay ignored/private. Reviewer HTTP serves anonymous cards, assigned own labels and progress only. No brokerage, external hosting, investment recommendations or portfolio-state changes are part of this cycle.

## Concrete schemas frozen before tests

**Five-year config:** exact fields `profile='five-year-v1'`, `study_id`, `id_salt`, `reviewers` (two declared roles), `detector_version='causal-geometry-v1'`, `detector_parameter_hash` (unchanged v1), `detector_source_file_sha256`, `as_of='2026-10-09'`, `context_years=5`, `target_sessions=20`, `source_symbols=['JNJ','JPM','KO']`, `shuffle_seed=20261012`, `holdout_locked=true`. Unsupported variations fail. Queue schema `pattern-review-five-year-v1`, same `cards/order/sealed/queue_hash` boundaries. Private cases include full `raw_window/visible_dates`, requested calendar start, actual dates/session count, input/source hashes, `split='calibration'`, `memberships=['random']` (a convenience case, not a probability sample), and predictions from precisely that full context. Summary identifies `phase='exploration'`, `sampling='convenience'`, no investment accuracy estimate. Legacy v1 config and byte-identical queue builds remain supported. Matching offsets use actual visible length; labels still accept only −19..0.

**Release:** exact API `freeze_evaluation(queue, calibration_labels, detector_version='causal-geometry-v1')`. Until a defensible separately tested correction exists, v1 is the supported evaluated version. Validate original queue and complete calibration history through the existing seams; both reviewers must label every calibration card (uncertain/invalid counts as completed review, never as certain truth). Preserve the full snapshot in `calibration_labels`, its SHA-256 in `calibration_labels_hash`, original queue identity/hash, source and parameter manifest, fixed matching policy, baseline/candidate identity and original-context committed predictions. `release_id` hashes these commitment fields before derived-queue creation. A final `release_hash` includes the derived holdout queue; no circular hash dependency.

The derived holdout queue contains only all original non-calibration cases as public anonymous cards, exactly original 180-session contexts. Config has the legacy frozen fields with `holdout_locked=false`, plus `profile='released-holdout-v1'`, `parent_queue_hash` and `release_id`. Its study ID is derived from the release ID, with its own queue hash and label journal. Private case memberships and original `time_holdout`/`symbol_holdout` assignments remain unchanged. `record_review_label` accepts the derived profile only with internally consistent hash/provenance. It cannot label a sealed original case or calibration card through the held-out queue.

Release commitments additionally include `evaluator_manifest` with the SHA-256 of both `review.py` and `evaluation.py`, plus a hash of the fixed consensus/matching/reporting protocol. Evaluation checks these against the currently trusted executable sources, reports them with the evaluated snapshot hash, and refuses scoring drift. A private `exposure_audit` records original-context interpretation, earlier developer-exposure limitations and source-disjoint five-year exploration after freeze. Tests/QA must exercise altered predictions/context with recomputed hashes, not only stale-checksum corruption. A valid outer hash alone cannot override the parent queue or trusted executable evidence.

**Evaluation:** `evaluate_detector(queue, labels, release, phase)` accepts `phase='calibration'|'holdout'`. Calibration labels must equal the frozen complete snapshot. Holdout labels must bind to the release's derived queue. Validate release/queue/label integrity and current trusted detector manifest, preserving inputs. Return snapshot hashes, phase, evaluated version, coverage, exact-consensus status, descriptive event counts/fractions and limitations. Holdout with any reviewer card missing has `status='pending_labels'`, progress only and `recognition_agreement=null`. Complete holdout metrics distinguish `time_holdout` versus `symbol_holdout` and random versus enriched strata. No individual-reviewer recognition scores. Labels remain append-only; each complete report identifies the full evaluated label snapshot hash.

**Runtime release gate:** the operator builds the immutable release from the preserved completed calibration snapshot, before the server can serve either real holdout or real five-year study. Same-input retries reproduce/reuse it; a different release cannot overwrite an active release or its labels. Five-year build additionally rejects any original source symbol. API study keys are a fixed whitelist, never directory paths. Only the assigned reviewer's own labels/progress are returned. After freeze the calibration HTTP view is read-only. Holdout and five-year labels have separate ignored directories. Public routes cannot return release manifests, predictions, private reports or other-reviewer observations. Default cycle-2 CLI remains usable; cycle-3 selection is explicit.
