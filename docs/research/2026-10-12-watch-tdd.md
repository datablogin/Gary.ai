`add(symbol, note='')`, `remove(symbol)`, and `view(as_of)`. Tests exercise these
methods with caller-supplied synthetic catalog records and real temporary
directories. The existing `coverage_report(snapshot, as_of)` derives clearance;
vendor observations and manual membership never establish reviewed eligibility.

The frozen catalog and response contract is in
`docs/watch-and-signals-contracts.md`. Persistence corruption and competing
processes are filesystem boundary tests. No internal collaborators are mocked.
All entries created in this implementation's tests are synthetic and temporary.

Implementation proceeds one observed failing behavior and minimal passing
implementation at a time. Red/green evidence and verification will be recorded
below as each slice completes.

## Result and boundaries

`add` and `remove` return `None`; callers obtain the resulting public state with
`view(as_of)`. `view` accepts a canonical completed-session ISO date. It returns
`manual-watch-view-v1` with `manual_list`, `radar_list`, and `buy_ready_list`,
named checks, plain Why, source links and cutoff/refresh information. Vendor
numbers remain unchanged in `check.value`; displayed P/E uses two decimals and
yield/revenue/SG&A observations use two decimal percentage places. Awaiting-entry
Why names the three approved entry choices.

Radar requires independently derived complete current coverage, management
clearance, an explicit expanded signals list, the current chart cutoff, and an
offset refresh receipt at or after that session's 16:00 New York close. A
completed eligible entry must be available exactly on the evaluation date,
with the current expanded detector version/hash and valid dates, pivots, levels,
and finite check evidence. A current technical sell requires stabilization and
review. A gap observation cannot independently clear entry. A fresh approved
entry with an unaffordable 100-share block is `allocation_blocked`, preserving
the distinction between stock selection and sizing.

The optional `observation_dates` mapping can date P/E, yield, revenue-growth and
SG&A-growth separately. Older dates mark only that observational check stale;
future or malformed dates require review. Absent dates retain shared chart and
receipt freshness. This does not replace or weaken reviewed coverage evidence.

Persistence uses a separate private directory (0700) and membership/lock files
(0600). An exclusive `flock` serializes updates; a temporary file is flushed and
fsynced, atomically renamed, and its directory fsynced. Removal archives original
membership and note with its removal time. Malformed state raises a clear error
and is never rewritten as an empty list. Twenty-four simultaneous synthetic
memberships across four processes verify the public restart boundary.

No market data was fetched, no personal ticker membership was manufactured,
and no paper-portfolio action, legacy-data access, dependency installation, or
Git mutation occurred in this work. Catalog acquisition, HTTP routing and UI
are owned by the parent implementation. Filesystem locking uses POSIX `fcntl`;
Windows portability is outside this approved local-Mac slice. A valid detector
event's source authenticity remains the explicitly supplied catalog adapter's
responsibility; the domain validates its documented evidence contract.
