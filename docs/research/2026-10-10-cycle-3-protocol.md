Building and synthetic verification of both workflows can proceed earlier.

Do not invent Gary judgments, convert unreviewed cards into negatives, or report a successful recognition result. ## What five years means with the available cache

The existing audit documents eight snapshots with **1,255 daily bars each, from 2021-10-11 through 2026-10-09**. This is a provider-returned five-year request, not a guarantee of exactly `5*252` sessions, audited corporate-action adjustment, exchange-calendar completeness, or point-in-time data. No raw data was reread here. [Coverage evidence](data-coverage.md), measured table and adjustment limitations.

For each new context, use a defined calendar interval ending at `as_of`: retain supplied completed-session bars after the date five calendar years earlier and no later than `as_of`. Freeze the inclusive/exclusive lower-bound and leap-day policy before implementation; a simple proposed policy is `(as_of minus five calendar years, as_of]`, with a February 29 anniversary clamped to February 28. This is a proposed local convention, not a required market rule. Record requested bounds, actual first/last dates, bar count, source hash and `full_requested_history_available` privately. Empty or malformed history is an error. Incomplete history is explicitly identified rather than padded, silently treated as full, or displayed with post-cutoff bars.

Every original calibration endpoint is at or before 2024-12-31. Its complete five-year prefix would require data before the cache starts in 2021. A full five-year context whose first bar is after that calibration boundary would need an endpoint about five years later, outside this cache. These are date-boundary deductions from the recorded cache and split, not newly measured endpoint counts. Therefore cycle 3 cannot honestly provide a full five-year, full-context-purged chronological holdout from these same snapshots.

Use a long-history overview plus a daily 180-session detail view. Keep all supplied daily bars in the underlying context; any display aggregation is presentation only and must not change detector inputs or completion-session selection. The 20-session target remains offsets −19 through 0 relative to the actual final bar. Price and volume normalization use only that context's permitted bars, with no post-cutoff observations. Do not mix adjusted close with provider OHLC. Variable context lengths and memorable curves weaken blinding; document that instead of claiming the original fixed-length anonymity guarantee still applies. [Original reviewer representation](2026-10-10-cycle-2-patterns.md), blinded representation and source basis.

## Preserve split validity with an exposure audit

Treat any source/date interval viewed by developers, reviewers, or a visual calibration procedure as exposure, even when no detector answer is shown. For every proposed **development or calibration** context `D` and every original holdout context `H`, flag overlap when source identity is equal and their closed actual bar-date intervals intersect. Also reject development exposure to reserved AMGN/SIRI sources. Record exposure role, reviewer/operator, protocol, context hash and cutoff. The trusted coordinator can perform this check using source identities and intervals; the researcher/developer need not receive holdout predictions, case IDs or charts.

Expanded calibration prefixes ending at or before 2024-12-31 can remain disjoint from the original later 180-session holdout contexts, although they are incomplete five-year prefixes. A full-cache view ending in October 2026 on one of the six calibration sources crosses into the original later holdout period. Such a view must follow the candidate freeze and original holdout evaluation, or the affected later holdout becomes exposed development evidence for that candidate. Showing reserved-source histories before freeze likewise compromises the whole-source reservation.

Expanded **holdout** contexts have a different problem: their older history can overlap calibration history even if no holdout data informed development. That can be a declared evaluation with shared historical covariates, but it is no longer the original full-context-purged experiment. Report it separately with overlap counts; preserve the original 180-session result and do not claim the broader result is untouched out-of-time validation. General temporal ordering and configurable gaps are described in the official [TimeSeriesSplit documentation](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html). The exact interval audit here is our conservative protocol choice, not an automatic guarantee supplied by that API.

Distinguish these cases in the release record:

| Exposure | Permitted interpretation |
| --- | --- |
| Original calibration only; baseline/candidate frozen before original holdout annotation | Original 180-session pilot recognition comparison, with the earlier first-cycle developer-exposure limitation |
| Original holdout annotation/evaluation completed before long-context exploration | Preserve the completed original result; later exploration cannot retroactively be called an independent test for a new candidate |
| Long holdout contexts overlap older calibration covariates, but no holdout bars influenced development | Separate long-context recognition result with explicitly overlapping history; no full-context-purge claim |
| Development/calibration context exposes original holdout bars or reserved sources before candidate freeze | Affected holdout is no longer independent for that candidate; use a new source/time reservation for a later confirmatory study |

Temporal/source reservations reduce specific contamination paths; eight correlated surviving sources and overlapping review windows still do not supply independent market-wide samples. The official [cross-validation guide](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-of-time-series-data) explains why nearby time-series observations challenge independent-sample assumptions. Its group-aware guidance supports retaining whole-source reservations, but does not certify this particular pilot.

## Corrections and independent calibration

Separate a **demonstrated contract correction** from a **visual rule change**. A contract correction requires a public `detect_patterns` example that fails against an already documented v1 behavior, followed by the smallest correction, a regression that passes, and independently checked causal/prefix and proportional-invariance behavior where relevant. It can proceed without pretending real labels already exist. Record the before/after behavior, rationale, detector version, parameter hash and source hash. Inspect code/documentation discrepancies first; a discrepancy is not proof of a defect until the public-seam example demonstrates it. [Approved detector seam](../agent-cycle-contracts.md); [v1 definitions](../pattern-parameters.md).

A change to shape thresholds, prior-trend rules, pivot/plateau treatment, expiry, roundedness, or pattern duration based on visual preference is calibration. Obtain Gary's independently saved calibration judgments plus a separately blinded reviewer set before treating it as alignment with Gary. Preserve `human`/`agent` provenance, uncertainty, invalidity and disagreement. No developer-generated expected event, QA-functional label or agent vote becomes Gary's judgment. Exactly two certain full event sets must agree under the original protocol; a different adjudication policy belongs to a separate version. [Review consensus implementation](../../src/gary/review.py), `summarize_review`; [original labels/consensus contract](2026-10-10-cycle-2-patterns.md).

Freeze an error inventory and the bounded intended corrections before inspecting holdout evidence. For an uncalibrated logic-only candidate, say so explicitly. Test-source answers must not choose thresholds or rules; official [data-leakage guidance](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage) explains the optimistic bias from using test information for model choices. That principle applies here to rule choices even though this detector has no `fit` method.

## Release governance and evaluation record

Use an append-only transition record: `calibration` → `candidate_frozen` → `holdout_annotation` → `scored` → `context_exploration`. The new-source page has its own study phase; opening it after the candidate freeze does not change the original evaluation's phase or permit its candidate to adapt to new judgments. Keep the user authorization and operator identity in the private release provenance; the present user request authorizes this bounded cycle, so the audit record is not a reason to request the same permission again. Releasing reviewer cards should not release predictions, source maps, other-reviewer labels or scores.

Before `holdout_annotation`, freeze:

- Parent study ID and original queue hash; original source hashes, case selection, split assignments, raw 180-session windows, memberships, exclusions and sampling provenance.
- Trusted original detector source/version/parameter hashes and separately identified candidate source/version/parameter hashes. Preserve original executable source before edits and verify its digest; reproducing baseline predictions must never execute today's candidate while calling it v1.
- Input protocol (`original_180` or separately named long context), target band, one-to-one matching policy, consensus policy, evaluator source hash, reporting strata and any planned baseline/candidate comparison.
- Development exposure audit and any compromised/unsupported evaluation interpretation. Do not remove awkward holdout cases after seeing errors; invalid/uncertain/disputed cases are reported as unscored with coverage.
- Candidate predictions for the original holdout windows, computed by the frozen candidate and sealed before independent labels are available. Keep original stored v1 predictions as baseline evidence; reproducibility validation should compare to the preserved original source.

A derivative release manifest should contain `parent_study_id`, `parent_queue_hash`, its own `study_id`/hash, `release_id`, timestamp/operator, phase, frozen baseline/candidate hashes, scoring protocol hash, context/input role, per-case context hashes and an exposure audit. Its label journal binds to that derivative hash and label context role. Never relabel existing 180-session observations as five-year observations or overwrite the original queue/journal. A historical queue loader should verify its own integrity and trusted archived detector identity rather than require that today's detector file match it; synthetic corruption tests must verify that the compatibility change cannot accept a forged hash. [Existing persistence and loading boundaries](../../src/gary/review_preview.py).

During annotation, return own label history and progress only. Do not show a score after every revision: that lets labels probe the hidden predictions. Freeze the completed independent label snapshot before producing the evaluation report; later corrections append an explicitly attributed report/label revision rather than erase the result. Adaptive reuse of ordinary holdout feedback can itself cause overfitting, as shown by [Dwork et al., Generalization in Adaptive Data Analysis and Holdout Reuse](https://arxiv.org/abs/1506.02629). A local lock or hash is not that paper's reusable-holdout algorithm; this bounded study should use a single frozen comparison and retire exposed holdout feedback from further candidate selection.

The report should distinguish `time_holdout` and `symbol_holdout`, random and enriched memberships, original and long contexts, baseline and candidate, certain consensus and remaining cases, and human-supported versus agent-only observations. Apply the original same-kind, one-to-one matching within three sessions with prediction availability no earlier than the independently labeled completion. Retain signed completion errors and availability delays. Report event counts and descriptive prediction/label match fractions with their denominators; null denominators remain null. Dual-membership counts overlap and must not be summed as independent samples. Original enrichment was chosen by v1: candidate results on it are a v1-selected comparison, not candidate-wide sensitivity. No cup labels/predictions implies no measured cup sensitivity. [Existing matching/summary](../../src/gary/review.py); [original study limitations](2026-10-10-cycle-2-patterns.md).

## Bounded acceptance evidence

Coordinator/developer/independent QA should verify the new behavior using synthetic queues and separately attributed functional studies before any real release:

1. Original queue/label artifacts remain byte-identical; archived detector bytes reproduce original predictions; a candidate code edit does not erase historical read access or weaken hash validation.
2. Five-year lower-bound, cutoff, leap-day convention, variable history and missing-history flags are explicit; malformed/future bars cannot enter context, normalization or detector inputs. Daily target selection works at the existing viewport and in the 180-session detail view.
3. A same-source interval overlap and reserved-source exposure block a clean-holdout claim; disjoint source/date cases pass. These checks inspect exposure metadata, not detector answers.
4. Release creates a separately hashed object/journal and binds the frozen candidate before labels; wrong parent/version/hash and duplicate/conflicting transitions fail without modifying the original study.
5. Reviewer HTTP responses omit predictions/identities/strata/other labels/scores, use the assigned reviewer, preserve local origin protections, and cannot access an unreleased case by guessed ID. Save/restart/retry/revision preserve provenance.
6. Synthetic holdout scoring exercises missing/uncertain/invalid/disputed observations, two-reviewer exact consensus, multi-event one-to-one timing, early-availability nonmatches, zero denominators, overlapping memberships and separate baseline/candidate results. No revision oracle exists.
7. Each detector correction has observed red/green public-seam evidence and independent recheck. Review/evaluation never changes fundamental clearance, paper orders or portfolio state.

This bounded cycle can establish reproducible contract corrections and an auditable recognition workflow.
